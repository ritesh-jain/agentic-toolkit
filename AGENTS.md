## ⚙️ Engine State Machine Specifications

The `start.js` engine operates in two directions based on input terminal flags (`process.argv` analysis). You are responsible for ensuring these execution blocks are fully realized and error-free:

### 1. Forward Synchronization Workflow (Default Execution)
Triggered when no flags are passed (`args` array is empty):
*   **Purge Phase:** Hard-delete (`fs.rmSync`) the destination directory (e.g., `.opencode/`) to eliminate stale configuration bleed or phantom files.
*   **Rebuild Phase:** Create clean, empty target subfolders: `[Target Tool Dir]/agents` and `[Target Tool Dir]/skills`.
*   **Layered Copy Phase:** Read the contents of this submodule's internal `./agents/` and `./skills/` folders, and write them cleanly down into the generated tool directory.

### 2. Reverse Save Workflow (`--save`)
Triggered when the `--save` argument is parsed:
*   Invert the workflow. Scan the generated active workspace runtime directory (e.g., `.opencode/skills/` or `.opencode/agents/`).
*   Locate any updated files or altered prompts modified during the user's IDE interaction, and copy them **back** into the submodule's tracking directory so they can be saved to git history.

### 3. Delta Selection Workflow (`--saveIfNew`)
Triggered when the `--saveIfNew` argument is parsed:
*   Perform an array comparison between the active files inside the runtime directory and the files inside the submodule tracking repository.
*   Isolate completely new scripts or agent Markdown profiles generated by the IDE agent on-the-fly, and copy **only** those new deltas back into this tracking repository.
